52-सप्ताह का सिस्टम डिज़ाइन शिक्षण रोडमैप (Roadmap) ​

52 सप्ताहों में प्रगतिशील योजना: पूर्वापेक्षाएं, वास्तुकला घटक, वितरित प्रणालियां, व्यावहारिक केस स्टडीज़ और साक्षात्कार तैयारी।

रोडमैप के चरण: 14

📖 चरण-दर-चरण विस्तृत पाठ्यक्रम ​

Phase 0 (Weeks 1-3): Prerequisites and vocabulary ​

  • 📚 क्या सीखना है: Client-server, DNS, HTTP, TLS, REST, databases, what a server actually is. Latency numbers every programmer should know.
  • 🛠️ क्या करना है: Write out the request path for a website you use, end to end, from keystroke to pixel.
  • 🎯 मील का पत्थर / सत्यापन: You can explain what happens when you type a URL, in detail.

Phase 0 (Weeks 3-6): Estimation and requirements ​

  • 📚 क्या सीखना है: Back-of-the-envelope maths, QPS, storage and bandwidth estimation, functional versus non-functional requirements.
  • 🛠️ क्या करना है: Estimate storage, QPS and bandwidth for three products you use daily. Check your assumptions.
  • 🎯 मील का पत्थर / सत्यापन: You can size a system in five minutes with defensible numbers.

Phase 1 (Weeks 6-10): The building blocks ​

  • 📚 क्या सीखना है: Load balancers, caches, CDNs, proxies, API gateways, message queues, object storage. What each does and costs.
  • 🛠️ क्या करना है: For each block, write when you would use it, when you would not, and what it fails at.
  • 🎯 मील का पत्थर / सत्यापन: You can name the right component for a requirement without hesitating.

Phase 1 (Weeks 10-14): Databases in depth ​

  • 📚 क्या सीखना है: SQL versus NoSQL, indexing, replication, sharding, consistent hashing, transactions, isolation, hot partitions.
  • 🛠️ क्या करना है: Design schemas and sharding strategies for three different products. Justify each partition key.
  • 🎯 मील का पत्थर / सत्यापन: You can defend a database choice against a challenging follow-up.

Phase 2 (Weeks 14-18): Distributed systems theory ​

  • 📚 क्या सीखना है: CAP and PACELC, consistency models, consensus, leader election, quorums, replication lag, clock problems.
  • 🛠️ क्या करना है: Watch the Martin Kleppmann lecture series. Read the DDIA chapters on replication and consistency.
  • 🎯 मील का पत्थर / सत्यापन: You understand why distributed systems are hard, not just that they are.

Phase 2 (Weeks 18-22): Caching and messaging ​

  • 📚 क्या सीखना है: Cache strategies, invalidation, eviction, multi-level caching, Kafka, queues, delivery guarantees, idempotency.
  • 🛠️ क्या करना है: Design the caching layer and the event flow for a product you know well.
  • 🎯 मील का पत्थर / सत्यापन: You can explain cache invalidation and exactly-once honestly, including the caveats.

Phase 3 (Weeks 22-28): Core case studies ​

  • 📚 क्या सीखना है: URL shortener, rate limiter, pastebin, key-value store, web crawler, notification system, chat, news feed.
  • 🛠️ क्या करना है: Work through the first 15 case studies on the Case Studies sheet. Write each one up before checking a solution.
  • 🎯 मील का पत्थर / सत्यापन: You can design any of the classic eight from a blank page in 45 minutes.

Phase 3 (Weeks 28-32): Harder case studies ​

  • 📚 क्या सीखना है: Uber, Netflix, WhatsApp, Google Docs, search, payments, ticket booking, distributed scheduler.
  • 🛠️ क्या करना है: Work through the remaining case studies. Focus on the deep dive rather than the boxes.
  • 🎯 मील का पत्थर / सत्यापन: You can go three follow-up questions deep on any component you drew.

Phase 4 (Weeks 32-35): Reliability and operations ​

  • 📚 क्या सीखना है: Redundancy, circuit breakers, rate limiting, graceful degradation, backpressure, disaster recovery, chaos.
  • 🛠️ क्या करना है: Take three of your designs and add the failure story: what breaks, what the user sees, how it recovers.
  • 🎯 मील का पत्थर / सत्यापन: Every design you produce now includes a failure discussion unprompted.

Phase 4 (Weeks 35-38): Observability and security ​

  • 📚 क्या सीखना है: Logging, metrics, tracing, SLOs, alerting, auth at scale, encryption, secrets, DDoS, data privacy.
  • 🛠️ क्या करना है: Add the observability and security layer to your existing designs. Define an SLO for each.
  • 🎯 मील का पत्थर / सत्यापन: You can answer 'how would you know it broke' for any system you design.

Phase 5 (Weeks 38-42): Low level design ​

  • 📚 क्या सीखना है: SOLID, design patterns, class diagrams, concurrency in objects, parking lot, elevator, BookMyShow, Splitwise.
  • 🛠️ क्या करना है: Solve 10 LLD problems with full class diagrams and working code. Amazon and Indian companies ask these directly.
  • 🎯 मील का पत्थर / सत्यापन: You can produce a clean class design and defend each abstraction.

Phase 5 (Weeks 42-45): Real architectures ​

  • 📚 क्या सीखना है: Engineering blogs from Netflix, Uber, Airbnb, Discord, Slack, Meta. How production actually differs from textbooks.
  • 🛠️ क्या करना है: Read two engineering blog posts a week. Write a paragraph on what surprised you in each.
  • 🎯 मील का पत्थर / सत्यापन: You can cite how a real company solved a problem you are designing.

Phase 6 (Weeks 45-48): Mock interviews ​

  • 📚 क्या सीखना है: Timed 45-minute designs, thinking out loud, diagramming under pressure, handling challenging follow-ups.
  • 🛠️ क्या करना है: Two mock interviews weekly. Record yourself. Watch it back; it is uncomfortable and effective.
  • 🎯 मील का पत्थर / सत्यापन: You can fill 45 minutes with structure, not filler.

Phase 6 (Weeks 48-52): Company-specific preparation ​

  • 📚 क्या सीखना है: Target company patterns, their engineering blog, their scale, their known question set. Behavioural preparation.
  • 🛠️ क्या करना है: Study your target company's architecture publicly. Prepare three of your own project stories in depth.
  • 🎯 मील का पत्थर / सत्यापन: You can connect your design choices to that company's actual problems.
