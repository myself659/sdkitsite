🛠️ केस स्टडीज़ का विस्तृत विश्लेषण ​

1. Design a URL shortener (TinyURL) ​

कठिनाई स्तर: Warm-up

  • ❓ पहले स्पष्ट करें: Read:write ratio, custom aliases, expiry, analytics, URL length
  • 🧱 मुख्य घटक: API layer, key generation service, KV store, cache, redirect service, analytics pipeline
  • ⚡ वास्तविक बाधा: Key generation without collisions at scale, and the read-heavy redirect path
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you avoid collisions? What if two servers generate the same key? How do you handle 100:1 reads?

2. Design a rate limiter ​

कठिनाई स्तर: Warm-up

  • ❓ पहले स्पष्ट करें: Per user or per IP, distributed or single node, hard or soft limit, what happens on breach
  • 🧱 मुख्य घटक: Gateway middleware, Redis counter store, algorithm (token bucket, sliding window log or counter)
  • ⚡ वास्तविक बाधा: Distributed counting without a race condition, and Redis becoming the bottleneck
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: Token bucket or sliding window? What if Redis goes down? How do you handle clock skew?

3. Design Pastebin ​

कठिनाई स्तर: Warm-up

  • ❓ पहले स्पष्ट करें: Text size limits, expiry, privacy, edit support, analytics
  • 🧱 मुख्य घटक: API, object storage for blobs, metadata database, cache, CDN
  • ⚡ वास्तविक बाधा: Storing large text efficiently and separating blob from metadata
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: Where does the text actually live? How do you expire content? Custom URLs?

4. Design a key-value store ​

कठिनाई स्तर: Core

  • ❓ पहले स्पष्ट करें: Consistency model, durability, single or distributed, size of values
  • 🧱 मुख्य घटक: Consistent hashing ring, replication, quorum reads and writes, gossip, Merkle trees
  • ⚡ वास्तविक बाधा: Partitioning, replication and the consistency versus availability choice
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you add a node? What is your replication factor? Handle a node failure mid-write.

5. Design a web crawler ​

कठिनाई स्तर: Core

  • ❓ पहले स्पष्ट करें: Scale, politeness, freshness, content types, duplicate handling
  • 🧱 मुख्य घटक: URL frontier, fetcher pool, parser, duplicate detector, content store, scheduler
  • ⚡ वास्तविक बाधा: Politeness (not overwhelming a host) and duplicate URL detection at billions of scale
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you avoid crawler traps? Respect robots.txt? Detect duplicate content?

6. Design a notification system ​

कठिनाई स्तर: Core

  • ❓ पहले स्पष्ट करें: Channels (push, SMS, email), volume, priority, opt-out, delivery guarantees
  • 🧱 मुख्य घटक: API, notification service, message queue per channel, third-party adapters, template service, worker pool
  • ⚡ वास्तविक बाधा: Third-party provider failure and avoiding duplicate sends
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you handle a provider outage? Prevent duplicates? Support user preferences?

7. Design a news feed (Facebook, Twitter) ​

कठिनाई स्तर: Core

  • ❓ पहले स्पष्ट करें: Feed ranking, follower counts, real-time expectations, media
  • 🧱 मुख्य घटक: Post service, fan-out service, feed cache, timeline store, ranking service, CDN
  • ⚡ वास्तविक बाधा: Fan-out on write versus read, and celebrity users with 100 million followers
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: Push or pull? What about a user with 50 million followers? How do you rank?

8. Design a chat system (WhatsApp, Messenger) ​

कठिनाई स्तर: Core

  • ❓ पहले स्पष्ट करें: One-to-one or group, online presence, message history, media, delivery receipts
  • 🧱 मुख्य घटक: WebSocket servers, service discovery, message store, presence service, notification service
  • ⚡ वास्तविक बाधा: Maintaining millions of persistent connections and message ordering
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you route to the right WebSocket server? Handle offline users? Group of 500?

9. Design a search autocomplete system ​

कठिनाई स्तर: Core

  • ❓ पहले स्पष्ट करें: Latency budget, personalisation, spell correction, trending
  • 🧱 मुख्य घटक: Trie service, aggregation pipeline, cache layer, CDN for popular prefixes
  • ⚡ वास्तविक बाधा: Sub-100ms latency and keeping the trie updated without downtime
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you update the trie? Handle trending queries? Filter inappropriate suggestions?

10. Design a video streaming service (YouTube, Netflix) ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Upload volume, resolutions, DRM, live or VOD, global reach
  • 🧱 मुख्य घटक: Upload service, transcoding pipeline, object storage, CDN, metadata service, recommendation service
  • ⚡ वास्तविक बाधा: Transcoding cost and CDN strategy; storage and bandwidth dominate the bill
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How does adaptive bitrate work? What does the CDN cost? Handle a viral video?

11. Design a ride-hailing service (Uber, Ola) ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Matching latency, surge pricing, driver tracking frequency, payment
  • 🧱 मुख्य घटक: Location service with geospatial index, matching service, trip service, pricing, notification, payment
  • ⚡ वास्तविक बाधा: Real-time geospatial matching and high-frequency location updates
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you index locations? QuadTree or geohash? Match at 1000 requests per second?

12. Design a food delivery system (Swiggy, Zomato) ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Three-sided marketplace, ETA accuracy, real-time tracking, peak load
  • 🧱 मुख्य घटक: Search, order service, matching, tracking, restaurant service, payment, notification
  • ⚡ वास्तविक बाधा: Peak-hour load concentration and three-party state consistency
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: What happens at 8pm on Friday? How do you compute ETA? Order fails mid-flight?

13. Design a payment system ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Idempotency, reconciliation, providers, currencies, compliance
  • 🧱 मुख्य घटक: Payment service, ledger, provider adapters, reconciliation job, webhook handler, fraud checks
  • ⚡ वास्तविक बाधा: Exactly-once semantics with money, and reconciliation with external providers
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: The webhook fires twice. Now what? How do you reconcile? Handle a provider timeout?

14. Design a ticket booking system (BookMyShow) ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Seat locking duration, concurrency at sale opening, payment timeout
  • 🧱 मुख्य घटक: Inventory service, seat locking (Redis with TTL), booking service, payment, notification
  • ⚡ वास्तविक बाधा: Preventing double-booking under extreme concurrency at a popular release
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: Two users click the same seat simultaneously. Design the lock. What if payment times out?

15. Design a distributed cache ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Eviction policy, consistency, size, hot keys
  • 🧱 मुख्य घटक: Consistent hashing ring, LRU per node, replication, client library, invalidation channel
  • ⚡ वास्तविक बाधा: Hot key distribution and invalidation across nodes
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you handle a hot key? Invalidate across the cluster? Add a node without losing everything?

16. Design a distributed message queue (Kafka) ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Ordering guarantees, durability, retention, consumer scaling
  • 🧱 मुख्य घटक: Brokers, partitioned append-only log, replication, consumer groups, offset store, coordinator
  • ⚡ वास्तविक बाधा: Ordering versus parallelism, and rebalancing without duplicate processing
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you guarantee ordering? What happens during a rebalance? Consumer crashes mid-batch?

17. Design Google Docs (collaborative editor) ​

कठिनाई स्तर: Expert

  • ❓ पहले स्पष्ट करें: Number of concurrent editors, offline support, history, conflict handling
  • 🧱 मुख्य घटक: WebSocket layer, OT or CRDT engine, document store, presence service, version history
  • ⚡ वास्तविक बाधा: Real-time conflict resolution with concurrent edits
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: OT or CRDT? Justify it. Handle offline edits reconciling on reconnect.

18. Design a distributed file storage (Dropbox, Drive) ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: File sizes, sync frequency, versioning, sharing, deduplication
  • 🧱 मुख्य घटक: Chunker, metadata service, block storage, sync service, notification service, dedup index
  • ⚡ वास्तविक बाधा: Efficient delta sync and block-level deduplication
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you sync only changes? Deduplicate across users? Handle conflicting edits?

19. Design a proximity service (Yelp, nearby places) ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Search radius, density variation, update frequency, ranking
  • 🧱 मुख्य घटक: Geospatial index (geohash or QuadTree), business service, search service, cache
  • ⚡ वास्तविक बाधा: Geospatial indexing with wildly uneven density between cities and countryside
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: Geohash or QuadTree? Why? Handle dense city centres versus rural areas.

20. Design a metrics and monitoring system ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Cardinality, retention, query patterns, alerting latency
  • 🧱 मुख्य घटक: Collection agents, ingestion pipeline, time-series database, downsampling, query service, alerting
  • ⚡ वास्तविक बाधा: Write volume and cardinality explosion; downsampling strategy
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you handle 2 million writes per second? Store a year of data affordably?

21. Design a logging and search system (ELK) ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Volume, retention, query latency, structured or unstructured
  • 🧱 मुख्य घटक: Log shippers, buffer (Kafka), indexing pipeline, search index, storage tiers, dashboard
  • ⚡ वास्तविक बाधा: Indexing cost at volume and hot versus cold storage tiering
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: What does indexing 10TB a day cost? How do you tier old logs?

22. Design an ad click aggregation system ​

कठिनाई स्तर: Expert

  • ❓ पहले स्पष्ट करें: Latency requirement, exactly-once, fraud, replay capability
  • 🧱 मुख्य घटक: Ingestion, Kafka, stream processor, aggregation store, reconciliation batch job, query service
  • ⚡ वास्तविक बाधा: Exactly-once counting with money attached, plus late and duplicate events
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you guarantee no double counting? Handle late events? Recompute after a bug?

23. Design a recommendation system ​

कठिनाई स्तर: Expert

  • ❓ पहले स्पष्ट करें: Cold start, latency, personalisation depth, feedback loop
  • 🧱 मुख्य घटक: Feature store, candidate generation, ranking model, serving layer, feedback pipeline, A/B framework
  • ⚡ वास्तविक बाधा: Serving latency with a large model, and the cold-start problem
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: New user with no history? Serve in under 100ms? Measure whether it works?

24. Design a stock exchange / trading system ​

कठिनाई स्तर: Expert

  • ❓ पहले स्पष्ट करें: Latency budget, ordering guarantees, fairness, audit
  • 🧱 मुख्य घटक: Order gateway, matching engine, order book, market data feed, ledger, audit log
  • ⚡ वास्तविक बाधा: Deterministic ordering at microsecond latency, and absolute correctness
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: Why a single-threaded matching engine? How do you guarantee fairness? Recover from a crash?

25. Design a distributed job scheduler ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Scheduling precision, at-least-once or exactly-once, failure recovery
  • 🧱 मुख्य घटक: Scheduler service, job store, distributed lock, worker pool, retry queue, dead letter queue
  • ⚡ वास्तविक बाधा: Ensuring a job runs exactly once across many scheduler instances
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: Two schedulers fire the same job. Prevent it. What if a worker dies mid-job?

26. Design a leaderboard system ​

कठिनाई स्तर: Core

  • ❓ पहले स्पष्ट करें: Scale, update frequency, ranking window, tie handling
  • 🧱 मुख्य घटक: Redis sorted sets, sharded by region or bucket, aggregation service, cache
  • ⚡ वास्तविक बाधा: Ranking millions of users in real time without recomputing
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: 10 million players updating constantly? Show a user their rank instantly?

27. Design an API rate-limited public API platform ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Tiers, quotas, keys, analytics, abuse
  • 🧱 मुख्य घटक: API gateway, key service, quota store, rate limiter, analytics pipeline, developer portal
  • ⚡ वास्तविक बाधा: Per-tenant quota enforcement across distributed gateways
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: How do you enforce quota across 20 gateway nodes? Handle a customer exceeding it?

28. Design a URL/content moderation system ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Latency, accuracy, human review, appeals, scale
  • 🧱 मुख्य घटक: Ingestion, ML classifier, confidence routing, human review queue, appeals service, audit log
  • ⚡ वास्तविक बाधा: Balancing false positives against latency, plus the human review bottleneck
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: What is your false positive tolerance? How do you handle appeals? Scale the human queue?

29. Design an e-commerce system (Amazon, Flipkart) ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Catalogue size, inventory accuracy, cart persistence, peak sales events
  • 🧱 मुख्य घटक: Catalogue service, search, cart, inventory, order, payment, fulfilment, notification
  • ⚡ वास्तविक बाधा: Inventory consistency during a flash sale and search at catalogue scale
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: Handle Big Billion Days traffic. Two users buy the last unit. Cart across devices?

30. Design a hotel or flight booking system ​

कठिनाई स्तर: Advanced

  • ❓ पहले स्पष्ट करें: Inventory sources, holds, cancellation, pricing volatility
  • 🧱 मुख्य घटक: Search service, inventory aggregator, hold service, booking, payment, supplier adapters
  • ⚡ वास्तविक बाधा: Inventory held across third-party suppliers you do not control
  • 🔄 अक्सर पूछे जाने वाले अनुवर्ती प्रश्न: The supplier says sold out after you took payment. Now what?
