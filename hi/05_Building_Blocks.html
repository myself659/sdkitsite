42 मौलिक आर्किटेक्चर घटक (Building Blocks) ​

कुल प्रविष्टियां: 42

#घटक का नामश्रेणीयह क्या करता हैकब उपयोग करेंकब उपयोग न करें (एंटी-पैटर्न)प्रचलित टूल्स
1Load balancerTrafficDistributes requests across multiple serversAny system with more than one serverA single-instance internal tool where it adds needless complexityNginx, HAProxy, AWS ALB, Envoy
2Reverse proxyTrafficSits in front of servers handling TLS, routing and bufferingTerminating TLS, serving static files, hiding internal topologyWhen your framework already handles it well at low scaleNginx, Caddy, Envoy, Traefik
3API gatewayTrafficSingle entry point handling auth, routing, rate limiting and quotasMicroservices with multiple clientsA single service where it becomes an unnecessary hopKong, AWS API Gateway, Apigee, Envoy
4CDNTrafficCaches content at edge locations near usersStatic assets, images, video, and any global audienceHighly personalised, uncacheable contentCloudflare, Akamai, CloudFront, Fastly
5DNS load balancingTrafficRoutes users to the nearest or healthiest regionMulti-region deploymentsFine-grained routing; DNS caching makes failover slowRoute 53, Cloudflare DNS
6Application cacheCachingIn-memory storage of frequently accessed dataRead-heavy workloads with tolerable stalenessData that must always be perfectly currentRedis, Memcached, Valkey
7Local/in-process cacheCachingCache inside the application processVery hot, small, rarely changing dataMulti-instance deployments needing consistencyCaffeine, Guava, in-memory maps
8Database read replicaDatabaseRead-only copies of the primary databaseRead-heavy workloads that tolerate replication lagRead-your-writes requirements without extra handlingPostgres streaming replication, MySQL replicas
9Relational databaseDatabaseACID transactions with a fixed schema and joinsAnything with relationships and correctness requirementsExtreme write scale or genuinely schemaless dataPostgreSQL, MySQL, Aurora
10Wide-column storeDatabaseDistributed store optimised for very high write volumeTime series, event data, messaging at massive scaleComplex queries and joinsCassandra, ScyllaDB, HBase, Bigtable
11Document databaseDatabaseFlexible schema, document-oriented storageEvolving schemas and nested dataHeavy relational joins and multi-document transactionsMongoDB, DynamoDB, Firestore
12Key-value storeDatabaseSimple, extremely fast lookups by keySessions, caching, feature flags, simple lookupsAny query that is not by primary keyRedis, DynamoDB, etcd
13Graph databaseDatabaseStores and traverses relationships as first-class dataSocial graphs, fraud rings, recommendationsSimple tabular data with no traversalNeo4j, Neptune, JanusGraph
14Time-series databaseDatabaseOptimised for timestamped metrics with downsamplingMonitoring, IoT, financial ticksGeneral-purpose transactional dataInfluxDB, TimescaleDB, Prometheus
15Search indexDatabaseFull-text search, faceting and relevance rankingAny product with a search boxExact lookups your primary database handles fineElasticsearch, OpenSearch, Solr, Typesense
16OLAP / data warehouseDatabaseColumnar storage for analytical aggregationDashboards, reporting, business analyticsTransactional, row-level operationsSnowflake, BigQuery, ClickHouse, Redshift
17Object storageStorageCheap, durable storage for large unstructured blobsImages, video, backups, data lakesLow-latency random access or transactional dataS3, GCS, Azure Blob, MinIO
18Block storageStoragePersistent disk attached to a compute instanceDatabases and anything needing a filesystemSharing across many instances simultaneouslyEBS, Persistent Disk
19Message queueMessagingBuffers work between producer and consumerDecoupling, absorbing spikes, background workGenuinely synchronous request-response needsRabbitMQ, SQS, Redis Streams
20Event log / streamMessagingDurable, replayable, ordered append-only logEvent sourcing, multiple consumers, replay capabilitySimple task queues where it is overkillKafka, Pulsar, Kinesis, Redpanda
21Pub/subMessagingOne publisher, many independent subscribersFan-out notifications and event broadcastingGuaranteed single-consumer processingKafka, Google Pub/Sub, SNS, NATS
22Task schedulerComputeRuns jobs on a schedule or after a delayReports, cleanups, reminders, retriesImmediate synchronous workAirflow, Temporal, Quartz, cron
23Worker poolComputeProcesses queued jobs asynchronouslyAny work too slow for the request cycleSub-millisecond operationsCelery, Sidekiq, BullMQ, Hangfire
24Serverless functionsComputeEvent-triggered compute with no server managementSpiky, low-volume, event-driven workloadsLong-running or latency-critical work (cold starts)Lambda, Cloud Functions, Azure Functions
25Container orchestratorComputeSchedules, scales and heals containerised servicesMulti-service systems at meaningful scaleA single small service; the complexity is not freeKubernetes, ECS, Nomad
26Stream processorProcessingContinuous computation over event streamsReal-time aggregation, windowing, enrichmentBatch work with no latency requirementFlink, Kafka Streams, Spark Streaming
27Batch processorProcessingLarge-scale scheduled data processingNightly reports, ETL, model training dataAnything needing sub-minute freshnessSpark, Hadoop, dbt, Airflow
28Rate limiterReliabilityCaps request rate per user, key or tenantAny public API or abuse-prone endpointTrusted internal traffic with known volumeRedis counters, Envoy, API gateway policies
29Circuit breakerReliabilityStops calling a failing dependency to allow recoveryAny synchronous call to another serviceLocal in-process callsResilience4j, Polly, Hystrix, Envoy
30Service discoveryReliabilityLets services find each other dynamicallyDynamic environments where instances come and goFixed, small, static deploymentsConsul, Eureka, Kubernetes DNS
31Service meshReliabilityHandles service-to-service traffic, security and telemetryLarge microservice estatesFewer than about ten services; the overhead dominatesIstio, Linkerd, Consul Connect
32Distributed lockCoordinationEnsures only one process performs an actionLeader election, preventing duplicate job executionWhen idempotency would solve it more simplyRedis Redlock, ZooKeeper, etcd
33Consensus / coordination serviceCoordinationAgreement on shared state across nodesLeader election, configuration, cluster membershipSimple systems where a database sufficesZooKeeper, etcd, Consul
34Configuration serviceCoordinationCentralised, dynamic application configurationMany services needing consistent, changeable configA single service where environment variables workConsul, Spring Cloud Config, AppConfig
35Feature flag serviceCoordinationToggles behaviour without a deploymentGradual rollouts, kill switches, experimentsVery small teams shipping infrequentlyLaunchDarkly, Unleash, Flagsmith
36Metrics and monitoringObservabilityCollects and stores numeric time-series signalsEvery production system without exceptionNever; this is not optionalPrometheus, Grafana, Datadog, CloudWatch
37Distributed tracingObservabilityFollows a single request across many servicesAny system with more than about three servicesA monolith where logs sufficeJaeger, Tempo, OpenTelemetry, Zipkin
38Centralised loggingObservabilityAggregates and indexes logs from all servicesAny multi-instance deploymentA single server you can SSH intoELK, Loki, Splunk, Datadog
39Error trackingObservabilityCaptures, groups and alerts on exceptionsEvery user-facing applicationNever; the free tiers make this trivialSentry, Rollbar, Bugsnag
40Identity providerSecurityCentralised authentication and token issuanceAny system with users, especially multi-serviceA single app with simple session authAuth0, Keycloak, Entra ID, Cognito
41Secrets managerSecurityStores and rotates credentials securelyEvery production systemNever; environment variables in git is the failure modeVault, AWS Secrets Manager, Doppler
42WAF / DDoS protectionSecurityFilters malicious traffic at the edgeAny public-facing serviceInternal-only services behind a VPNCloudflare, AWS WAF, Akamai
